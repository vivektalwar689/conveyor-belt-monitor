Summary

How to read the result

  • Severity follows the dashboard's rules for a confirmed belt defect: tear or hole = high, puncture or impact damage = medium, wear = low. On the belt, severity also rises with the defect's physical size and growth over revolutions. A single photo has no scale and no history, so those are not used here.
  • One photo is one look. On the conveyor, a detection becomes an alert only after it is seen again at the same belt position on another revolution, which filters out most one-off false positives. Here you see raw single-image detections.
  • Expect mistakes. On scenes it never saw in training, the detector reaches only 0.06–0.12 box mAP@0.5. It often finds the damaged region but draws a different box or class, and it misses some damage. The deployed model was fine-tuned on defect-free crops: it raises far fewer false alarms on healthy belt but is less sensitive. The baseline sees more and is wrong more often. See the evaluation.
  • Samples are held-out test scenes from the public dataset (MIT licence), never used for training. Their dashed boxes are the dataset's own labels, so you can see where the detector is right, where it misses damage, and where it picks a different class. The file names keep the dataset's original split prefixes (train_, valid_, test_). That split leaked near-duplicate scenes between training and test, so the project re-split the data by scene, and all eight are in the new test split.
  • The browser resizes images a little differently from OpenCV (by under one grey level on 99% of pixels). Confidences therefore differ from the Python pipeline by about 0.01, and a borderline box can appear or disappear. Long, thin tears are the most sensitive: their box can end tens of pixels earlier or later.
